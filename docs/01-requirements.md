# 01 需求与成功标准

## 用户与目标

主要用户是内容运营/审核人员。他们需要从待处理素材中识别可排期、需补资料、存在风险或时段冲突的项目，并得到一份可确认的草稿，不希望 Agent 代替人做越权发布或悄悄改变硬性要求。

## 输入与输出

输入包含请求 ID、素材 ID、发布日期、要求时刻、是否为硬性时刻、备选时刻。素材元数据、审核规则和已有排期由工具读取。

每次运行必须返回：素材审核状态、风险/缺失原因、要求与建议时段、待确认状态、草稿保存结果、是否重复、明确的 `published: false`，以及包含工具参数、返回摘要、下一动作和决策依据的 Trace。

## 范围

核心范围：单请求单素材的 CLI 工作流；素材读取、规则检查、时段查询、草稿保存四个工具；真实模型与离线 Mock 两种决策入口；步数上限和幂等；六项验收场景。

不在范围：UI、线上部署、真实发布、多 Agent、人工确认回写、多素材批处理、生产数据库、鉴权和并发控制。

## 成功标准

| 验收点 | 可观察标准 |
|---|---|
| 正常排期 | 审核通过、要求时段可用、草稿成功、无需确认 |
| 信息缺失 | 列出缺失字段，查时段前结束，不保存 |
| 规则风险 | 列出风险码和原因，阻断保存 |
| 时段冲突 | 观察冲突后选择可用备选，标记待用户确认 |
| 重复提交 | 相同 request_id 与内容复用同一 draft_id，库中仅一份 |
| 保存失败 | `save_failed` 且 `saved: false`，不虚报成功 |
| 硬性要求 | 冲突时不改期、不保存，返回需确认 |
| 执行上限 | 达上限返回 `incomplete_step_limit` |

测试成功标准为所有自动化测试通过，且 `examples/` 至少覆盖正常、资料不足、工具失败，并覆盖上述全部验收点。
