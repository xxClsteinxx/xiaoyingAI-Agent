# 05 复盘

## 最难的问题

最难的不是把四个工具串起来，而是划清“模型自由决策”和“业务不可违反约束”的边界。只在提示词里写“不要越权”不够可靠，因此把风险复核、时段占用、硬性时间、待确认和幂等都下沉到工具；最终输出再与真实工具观察对账，防止模型用文字虚报成功。

第二个难点是让离线可复现与真实 ReAct 要求同时成立。解决方式是同一 Agent 循环依赖一个决策接口：离线策略用于测试工程链路，Responses API 适配器用于真实模型逐轮选动作；输出显式标记 `real_model`，避免夸大 Mock 证据。

## 学习收获

- Agent 的价值在于基于观察改变动作，不在于框架名称。
- 风险类系统应让模型做语义选择，让确定性代码守住不可违反的约束。
- Trace 应记录可审计的业务依据，而不是模型内部思维过程。
- 幂等不仅是“查到就返回”，还要校验同一个 key 的载荷是否一致。
- 失败状态是一等输出：保存失败和未执行保存必须与保存成功清楚区分。
